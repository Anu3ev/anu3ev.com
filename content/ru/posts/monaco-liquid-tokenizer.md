Обычный фрагмент шаблона витрины:

```liquid
<a class="product-card {% if product.available %}in-stock{% endif %}"
   href="{{ product.url }}">{{ product.title | escape }}</a>

<script type="application/ld+json">
  { "@context": "https://schema.org", "@type": "Organization" }
</script>
```

В нём есть HTML, Liquid в разметке, Liquid внутри значения атрибута и блок `script`, в котором находится JSON, а не JavaScript. Если открыть его в стандартном HTML-режиме Monaco, Liquid в разметке окажется простым текстом, а внутри атрибута окрасится как обычная строка. Чтобы подсвечивать такой файл и давать в нём подсказки, редактор должен знать, какой язык находится в каждом месте.

На платформе inSales более 60 000 магазинов. Партнёры-разработчики, специалисты техподдержки и технически подготовленные владельцы магазинов правят код шаблонов и виджетов прямо в админке. Старая интеграция CodeMirror не подсвечивала смешанный синтаксис, не давала контекстных подсказок и Emmet, который разворачивает короткие аббревиатуры в готовую разметку или CSS. Поэтому мы решили перейти на Monaco Editor, движок, на котором построен VS Code. Я реализовал кастомную сборку Monaco для inSales и с июня 2022 по октябрь 2025 года развивал и сопровождал её.

Monaco даёт сам редактор, модели документов (открытые файлы вместе с их языком) и API языковых провайдеров, через которые подключаются подсветка и подсказки. Но о предметной области inSales Monaco ничего не знает, а расширения VS Code к браузерному Monaco не подключаются. Поэтому смешанный язык пришлось описать средствами самого Monaco.

## После Liquid токенизатор возвращается туда, откуда вошёл

Подсветку в Monaco задаёт токенизатор: он делит текст на токены, и каждый фрагмент окрашивается по типу своего токена. Токенизатор пишется на Monarch, встроенном в Monaco декларативном формате. Описание на Monarch состоит из состояний, и в каждом из них правила находят фрагмент текста, назначают ему тип токена и могут перевести токенизатор в другое состояние.

Я зарегистрировал кастомный смешанный язык HTML и Liquid и описал для него токенизатор. Он различает HTML-теги и атрибуты, вывод Liquid через `{{ … }}`, управляющие конструкции через `{% … %}`, Liquid-комментарии и блоки `raw`, переменные, операторы, встроенные фильтры и теги inSales.

Сложнее всего было с Liquid внутри значения атрибута. Значение может целиком состоять из Liquid-выражения или содержать обычный текст вперемешку с несколькими вставками Liquid. После закрывающего `}}` или `%}` токенизатор должен вернуться в состояние значения атрибута, а не подсвечивать остаток строки как Liquid.

Для этого в Monarch есть стек состояний. Правило с `next: '@liquidOutput'` добавляет новое состояние в стек, а правило с `next: '@pop'` убирает его и возвращает токенизатор в предыдущее состояние:

```ts
// Упрощено: закрывающие теги, пробелы и часть состояний опущены
monaco.languages.setMonarchTokensProvider('liquid', {
  tokenizer: {
    root: [
      [/\{\{/, { token: 'delimiter.liquid', next: '@liquidOutput' }],
      [/\{%/, { token: 'delimiter.liquid', next: '@liquidTag' }],
      [/<[\w-]+/, { token: 'tag', next: '@tag' }],
    ],
    tag: [
      [/[\w-]+/, 'attribute.name'],
      [/="/, { token: 'attribute.value', next: '@attributeValue' }],
      [/\/?>/, { token: 'tag', next: '@pop' }],
    ],
    attributeValue: [
      [/\{\{/, { token: 'delimiter.liquid', next: '@liquidOutput' }],
      [/\{%/, { token: 'delimiter.liquid', next: '@liquidTag' }],
      [/"/, { token: 'attribute.value', next: '@pop' }],
      [/[^"{]+|\{/, 'attribute.value'],
    ],
    liquidOutput: [
      [/\}\}/, { token: 'delimiter.liquid', next: '@pop' }],
      [/\|\s*[\w-]+/, 'predefined.liquid'],
      [/[\w.]+/, 'variable.liquid'],
    ],
    liquidTag: [
      [/%\}/, { token: 'delimiter.liquid', next: '@pop' }],
      [/[\w.]+/, 'keyword.liquid'],
    ],
    // комментарии и raw устроены так же
  },
})
```

Одно и то же состояние `liquidOutput` используется и в тексте документа, и в значении атрибута, а куда вернуться после `}}`, определяет стек. В языковой конфигурации я также задал пары скобок, автоматическое закрытие конструкций и отступы после открывающего HTML-тега. Поэтому смешанный файл ведёт себя как один язык, а не как набор раскрашенных фрагментов.

## Внутри script и style начинается другой язык

В первой версии код внутри `<script>` и `<style>` не подсвечивался совсем. Поэтому я добавил в токенизатор переключение на вложенный язык: внутри `<script>` на JavaScript или JSON, внутри `<style>` на CSS, а после закрывающего тега обратно на HTML. В Monarch за это отвечает свойство `nextEmbedded`: после правила с ним токенизатор передаёт текст вложенному языку, пока не встретит правило с `nextEmbedded: '@pop'`.

Для `script` важен атрибут `type`: в шаблонах встречаются обычный JavaScript, `application/json`, `application/ld+json` и другие значения. Если передавать значение `type` во вложенный язык как есть, как это делает стандартный HTML-режим Monaco, то `application/ld+json` указывает на язык, которого в сборке нет. Редактор не должен пытаться загрузить несуществующий языковой сервис, поэтому я явно сопоставил распространённые значения `type` с поддерживаемыми языками, а для остальных выбрал JavaScript:

```ts
// Упрощено: показаны только правила для <script>
tokenizer: {
  root: [
    // Пока атрибут type не найден, содержимое считается JavaScript
    [/<script/, { token: 'tag', next: '@script.javascript' }],
    // остальные правила HTML и Liquid
  ],
  // Вторая часть имени состояния ($S2) хранит язык содержимого
  script: [
    [/type\s*=\s*"application\/(?:ld\+)?json"/,
      { token: 'attribute', switchTo: '@script.json' }],
    [/type\s*=\s*"[^"]*"/,
      { token: 'attribute', switchTo: '@script.javascript' }],
    [/[\w-]+(?:\s*=\s*"[^"]*")?|\s+/, 'attribute'],
    [/>/, { token: 'tag', next: '@scriptBody', nextEmbedded: '$S2' }],
    [/<\/script\s*>/, { token: 'tag', next: '@pop' }],
  ],
  scriptBody: [
    // Закрывающий тег возвращает токенизатор
    // из вложенного языка в состояние script
    [/<\/script\s*>/,
      { token: '@rematch', next: '@pop', nextEmbedded: '@pop' }],
  ],
}
```

Атрибут `type` встречается в открывающем теге раньше символа `>`, а язык содержимого нужен именно на этом символе. Поэтому язык хранится во второй части имени состояния. Правило для `type` переключает `script.javascript` на `script.json`, а на символе `>` значение `$S2` попадает в `nextEmbedded`. Любое другое значение `type` оставляет JavaScript, поэтому редактор не ищет языковой сервис для неизвестного типа.

## Подсказки узнают язык у модели, а не по тексту

Подсветка решала только половину задачи. Когда курсор находится внутри `<script>`, пользователю нужны подсказки JavaScript, а не HTML-теги, атрибуты или Liquid-сниппеты. Внутри `<style>` должны работать подсказки CSS и Emmet.

Для этого я зарегистрировал провайдер автодополнения, который возвращает разные наборы подсказок в зависимости от языка в позиции курсора. Сначала язык определялся регулярными выражениями по тексту перед курсором:

```ts
// Было (упрощено): ищем незакрытый <script> в тексте перед курсором
const { lineNumber, column } = position
const textBefore = model.getValueInRange(
  new monaco.Range(1, 1, lineNumber, column)
)
const isInsideScript =
  /<script\b[^>]*>(?:(?!<\/script>)[\s\S])*$/.test(textBefore)
```

Такая проверка была хрупкой, особенно для `script` с нестандартным значением `type`. Она видит только теги и не знает, что `type="application/ld+json"` означает JSON. Каждый случай, который уже учёл токенизатор, пришлось бы повторять ещё одним регулярным выражением.

В конце сентября 2024 года я заменил её на метод `model.getLanguageIdAtPosition`. Для каждой строки Monaco хранит токены и язык каждого токена, поэтому он знает, какой вложенный язык находится в конкретной позиции:

```ts
monaco.languages.registerCompletionItemProvider('liquid', {
  provideCompletionItems(model, position) {
    const { lineNumber, column } = position
    const word = model.getWordUntilPosition(position)
    const range = new monaco.Range(
      lineNumber, word.startColumn, lineNumber, word.endColumn
    )
    // Например, 'javascript' внутри <script>
    // и 'liquid' в обычной разметке
    const languageId =
      model.getLanguageIdAtPosition(lineNumber, column)

    return { suggestions: snippetsFor(languageId, range) }
  },
})
```

Функция `snippetsFor` возвращает сниппеты для этого языка. Сниппетами называются готовые фрагменты кода, которые вставляются по короткому слову. В сборке три набора: 122 сниппета для Liquid, 152 для JavaScript и 166 для CSS, всего 440. HTML и Liquid при этом остаются одним языком, поэтому метод отличает разметку от вложенных JavaScript и CSS, а не HTML от Liquid.

Теперь на вопрос, какой язык находится под курсором, отвечает только токенизатор. Если исправить в токенизаторе ошибку во вложенном языке, подсказки в этом месте тоже станут правильными.

## Одна сборка для пяти интерфейсов

Сначала редактор работал только в окне кода виджета. По мнению инфраструктурной команды, тяжёлый Monaco сильно нагружал серверы компании, и в декабре 2022 года она предложила вынести его в отдельный репозиторий. Эту задачу поручили мне. Я оформил сборку в новом репозитории как внутренний gem для Rails-приложения inSales и добавил небольшой API, через который редактор подключают и старые страницы админки, и Vue-интерфейсы. К 2025 году одну сборку подключили к пяти интерфейсам: окну кода виджета, полному редактору шаблона, шаблонам писем по заказам, [«Брошенным корзинам»](/ru/work/abandoned-carts/) и «Диалогам», где магазин настраивает уведомления о заказе для мессенджеров, SMS и email. Исправление токенизатора попадает во все пять с новой версией gem. Подробнее о сборке, воркерах и API рассказано в [кейсе о редакторе кода](/ru/work/monaco-editor/).

## Что я бы посоветовал при описании своего языка в Monaco

- Держите знание о том, где какой язык, в токенизаторе. Провайдеру подсказок достаточно спросить модель через `getLanguageIdAtPosition`, и регулярные выражения по тексту перед курсором не понадобятся.
- Продумайте возврат из вложенных конструкций: после вставки токенизатор должен вернуться в то состояние, из которого в неё вошёл. В Monarch это делает стек состояний.
- Явно сопоставьте значения `type` во вложенных блоках с языками и задайте язык по умолчанию для остальных.
