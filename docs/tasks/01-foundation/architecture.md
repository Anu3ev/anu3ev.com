# Архитектура

## Контракт продукта

Портфолио Vue/TypeScript-разработчика: главная, проекты, отдельный кейс, блог, статья, об авторе, контакты, privacy и настоящая 404. Контактные действия ведут к существующим email, Telegram и LinkedIn. Форму, которая лишь имитирует отправку, не добавляем.

Рабочее решение новой реализации: основной язык — английский, русская версия имеет префикс `/ru`. Slug одинаковый в обеих версиях, что позволяет переключать язык на соответствующей странице. Навигация: Home, Work, Blog, About, Contact. Блог: не более 10 статей на страницу, отдельные индексируемые URL страниц и корректная 404 для отсутствующих страниц.

## ADR-001: Nuxt 4, Vue 3, TypeScript, статическая генерация

Публичный сайт не требует персонализации или приватного API. `nuxt generate` создаёт HTML для каждой страницы. Это даёт поисковым системам готовый контент, сокращает TTFB и исключает постоянный сервер и базу данных. Генерируемые файлы переносимы между хостингами.

Структура:

```text
app/
  assets/css/       дизайн-токены и общая типографика
  components/      содержательные общие UI-компоненты
  composables/     локализация и SEO с владельцем на уровне Nuxt
  layouts/         общий каркас
  pages/           маршруты и сценарии страниц
  utils/           чистые контракты пагинации и URL
content/
  en/, ru/         Markdown-кейсы и статьи
  settings/        редактируемая информация об авторе
public/
  admin/           Sveltia CMS и её декларативная схема
  images/          оптимизированные публичные изображения
scripts/           генерация метаданных, проверка контента, релиз
tests/
  unit/            критичные чистые контракты
  e2e/             публичные пользовательские сценарии и axe
.github/workflows/ проверки и версионные релизы
docs/tasks/        решения, результаты и review каждой задачи
```

Nuxt Content хранит статьи и кейсы в Git, валидирует их схемой и предоставляет типизированные запросы. Контент фильтруется по `published`, локали и дате. Черновики не должны попадать в HTML, payload, RSS и sitemap.

Макет Home/Blog задаёт трёхколоночную personal-space структуру: левое меню, центральная лента и правый профиль. Portfolio/Contacts используют ту же синюю палитру. Tailwind используется через официальный Vite-плагин; смысловые CSS-классы отвечают за устойчивые компоненты и дизайн-токены. Глобальный Pinia-store добавляется только при реальном общем доменном состоянии. Для текущего сайта Vue/Nuxt state достаточно; наличие Pinia в экспертной области не является причиной искусственно добавлять store.

## ADR-002: Sveltia CMS и GitHub

`/admin/` — бесплатная open-source CMS с редактором Markdown, полями статьи, обложками, датами, категориями, проектами и настройками профиля. Авторизация опирается на разрешения GitHub. В коде и в публичной сборке нет токенов.

Для одного технического владельца выбираем поддерживаемый Sveltia вход с fine-grained GitHub PAT: только этот репозиторий, Contents read/write. Для editorial workflow требуется также Pull requests read/write. CMS хранит токен в localStorage браузера — это существенный компромисс: входить следует с доверенного устройства и выходить после работы на общем устройстве. Не выдаём это за серверную сессию или готовый OAuth.

Контент сохраняется коммитом, затем GitHub CI проверяет схемы и тесты. Версионный релиз и публикация связаны с production-коммитом. Инструкция владельцу опишет точный рабочий путь. OAuth можно добавить отдельным бесплатным Cloudflare Worker после регистрации GitHub OAuth App, если потребуется многопользовательская редакция.

Документация: [Sveltia GitHub backend](https://sveltiacms.app/en/docs/backends/github), [Nuxt Content static hosting](https://content.nuxt.com/docs/deploy/static).

## ADR-003: бесплатная публикация

Текущий GitHub-репозиторий `Anu3ev/anu3ev.com` приватный; доступ admin/push подтверждён. Существующий Vercel account/team доступен. Выбираем статический деплой на существующем бесплатном тарифе Vercel с GitHub integration, без платных ресурсов, функций, базы данных и аналитического SDK. Приватность репозитория сохраняется. GitHub Pages остаётся переносимой альтернативой, если существующий GitHub Teams даёт нужную возможность; смена visibility не требуется.

Production должен иметь постоянный HTTPS-адрес `*.vercel.app`. Домен `anu3ev.com` подключается только при доступном DNS; отсутствие доступа к регистратору не блокирует публичный сайт. Canonical, sitemap, robots и OG используют реально доступный основной origin. После переноса домена origin меняется в одном конфигурационном значении, сайт пересобирается.

CI: установка по lockfile, валидация контента, ESLint, TypeScript, unit, генерация, browser smoke и accessibility. Релиз: тег semver, GitHub Release, архив статической сборки. Публикация проходит по GitHub-коммиту. Конкретный механизм gating фиксируется после проверки доступных API; недоступные настройки не объявляем выполненными.

## ADR-004: SEO и производительность

Каждая индексируемая страница: уникальные title/description, canonical, Open Graph, Twitter card, `lang`, соответствующие alternate/hreflang. JSON-LD: Person/WebSite на главной, BreadcrumbList на внутренних страницах, BlogPosting для статьи, CreativeWork для кейса. JSON-LD сериализуется с экранированием `<`.

Sitemap содержит только опубликованные канонические маршруты. `robots.txt` сообщает sitemap и исключает admin; robots — не механизм авторизации. RSS доступен для блога. 404 и admin не индексируются. Пагинация не канонизируется целиком на первую страницу. Даты и заголовки берутся из контента, а не из системного времени.

Изображения имеют размеры, WebP, отложенную загрузку ниже первого экрана; hero загружается приоритетно. Шрифты локальные, `font-display: swap`. Никаких тяжёлых редакторов или iframe при первом рендере. Учитываем reduced motion. Лабораторный Lighthouse не выдаём за полевые Core Web Vitals: полевые данные появляются после реального трафика.

## ADR-005: будущие playground-проекты

Кейс уже имеет стабильный slug, внешние repository/demo links и опциональное поле demo URL. Будущие `/playground/:slug` подключаются лениво, каждый с собственной областью состояния и cleanup. Monaco, FabricJS и TinyMCE не импортируются в общий layout. Если понадобится iframe, добавляются sandbox/permissions, title и явная кнопка загрузки. Приватные исходники inSales и данные клиентов не публикуются.

## Макет и доступность источников

Источник нового дизайна: MagicPath `463007080014573568`. API ответил `EXTERNAL_AGENT_API_QUOTA_EXCEEDED`; анонимный браузер перенаправил на главную. Пользователь предложил войти в браузере; ссылка открыта. После предложенной пользователем авторизации все четыре экрана прочитаны через браузер. Новые снимки находятся в `docs/reference/magicpath`. Палитра Home/Blog: графит `#101216`, синий `#86adff`, Inter, три колонки с лентой по центру. Прежние визуальные решения заменяются реальным макетом.

## Применение code-writer

Проверены исходник в Obsidian и установленная копия всего каталога: рекурсивный diff пустой, обе quick_validate успешны. Fallow baseline выполнен до кода: JS/TS entry points отсутствуют, поэтому нулевые показатели baseline не измеряют качество будущего приложения.

Внешний ввод валидируется схемами и содержательными предусловиями; пагинация проверяет допустимость номера и размера. Возникает конкретный конфликт правила «minimum 2 runtime assertions per function» с запретом defensive noise в простых Vue computed, библиотечных callbacks и обработчике переключения темы: их внутренний контракт уже гарантирован Nuxt/Vue. В рамках поручения самостоятельно принимать технические решения выбираем не добавлять фиктивные assertions в эти места; это явное отклонение от буквального счётчика, а не заявление о его выполнении. Контракты проверяются тестами и на внешних границах.

Новые функции имеют JSDoc, объект-параметр для нескольких собственных аргументов, плоский ход чтения, без рекурсии и `any`. Осмысленные компоненты разделяются по владельцу; не создаём микро-helper-ы ради лимита строк. Перед каждым UI-этапом определяем keyboard/focus/error acceptance. После этапа — самопроверка diff, исправления и повторный прицельный проход. Независимое ревью не подменяем самопроверкой.
