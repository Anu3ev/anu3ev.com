# Review и исправления

Проверены требования, источники, все новые владельцы поведения и связи между static routes, SEO, content database, изображениями и browser tests. Это самопроверка автора и автоматические проверки, а не независимое ревью.

1. **Публикация и маршруты.** Один `createPublicPaths` используется Nitro и sitemap. Реальная временная Nuxt-сборка содержит ровно 12 синтетических статей на язык: первая страница 10, вторая 2, прямой reload и русский эквивалент работают; третья возвращает 404. Fixture не меняет исходное содержимое и не попадает в deployment. Копируются только объявленные app inputs, без Git, `.env`, browser profiles; build/cache изолированы.
2. **SEO.** Canonical нормализует trailing slash, hreflang ведёт на эквивалент, JSON-LD описывает тот же канонический документ. Ошибка с `/` в mainEntityOfPage после static-server redirect найдена browser test и исправлена также для кейсов. Article `dateModified` не выдумывается. Новые статьи датированы днём запуска, одинаковые даты сортируются по slug детерминированно.
3. **JSON-LD и XML.** Inline JSON экранирует `<`, XML — текст и атрибуты. Unit-тест проверяет закрывающий script в пользовательском заголовке. Два RSS содержат только публичные записи и проходят XML parsing. Сайт имеет manifest, favicon и apple-touch-icon.
4. **Доступность.** Первый полный прогон выявил label-in-name у монограммы, недостаточный контраст светлых labels и неясные имена пагинации. Исправлены все связанные места; декоративная заливка отделена от текстового цвета. Логотип сохраняет видимое `a.` в доступном имени, ссылки страниц называются Page N. Русская 404 определяется по URL, включая неизвестные routes.
5. **Контраст на телефоне.** Lighthouse нашёл CTA поверх графики cover. Кнопка получила непрозрачный фон текущей темы; добавлены mobile axe checks для обеих тем.
6. **Performance.** Первый mobile Lighthouse: 86/96/100/100, LCP 3.4 s. По waterfall убран сетевой blocking theme request: маленький bootstrap остаётся исходником, встраивается в head до paint. Шрифты локальные и preloaded; Latin/Cyrillic hint URLs нормализованы, чтобы SSR-relative и client-absolute формы не создавали вторую загрузку при hydration. Есть отдельный regression test. Предзагрузка destination routes происходит при interaction, не конкурирует с первым paint.
7. **Изображения.** Build-time Sharp создаёт 640/960/1200 WebP для card srcset. Полные originals остаются у кейсов. Генерируемые каталоги очищаются своим владельцем. При смене исходной обложки в уже запущенном dev требуется `pnpm assets:prepare` или restart.
8. **Сжатие.** Nitro создаёт Brotli/Gzip, preview действительно возвращает `Content-Encoding: br`. Внешний CDN остаётся бесплатным; runtime image service отсутствует.
9. **Читаемость.** Vue-разметка разнесена по смысловым блокам с сохранением inline spaces. Общий опубликованный post projection/sort принадлежит `app/queries/posts.ts`; Home и Blog не дублируют политику. Генерация fixture articles отделена от изоляции checkout/cache. Composables проверены отдельно: router — source of truth для locale; нет singleton между SSR users, скрытых root event chains и timers без cleanup.
10. **Факты.** С актуальным резюме (обновлено 16.10.2026) сверены даты inSales: frontend заканчивается сентябрём 2026. Старый inventory не используется.

Fallow после исправлений: нет dead code/import/export/cycle/boundary/duplication/function complexity findings. Verdict `warn` включает CSS heuristics и четыре conditional `test.skip` при полностью пустом published content. В фактическом полном прогоне skips **0**. Эти условия сохраняют возможность администрировать пустые коллекции. `router-link-exact-active` создаёт Vue Router; `--font-sans` определяет Tailwind; reduced-motion `!important` намеренно перекрывает motion. Простые scoped selectors и относительный размер inline-code проверены по cascade; они не заменялись лишними utility/classes ради score.

Admin static `noindex,nofollow` и добавляемый Sveltia `noindex` совместимы: Google агрегирует directives. Проверка учитывает оба, не требует единственного vendor tag. [Google Search Central](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag).

Ограничения: browser engine — Chromium. Axe/Lighthouse не являются полной ручной сертификацией WCAG. Core Web Vitals здесь лабораторные; полевые INP/CrUX появятся только после реального трафика. Первый PAT sign-in/write владелец выполняет сам; токен не извлекался.
